# 召回块固定插在深度 1,历史只追加

DeepSeek 的上下文缓存只看请求开头是否完全一致(前缀匹配),第一个不同的字之后全部按原价计费。召回内容每轮都会变,所以不放进系统提示词,而是作为一条 system 消息固定插在最新一条用户消息之前(深度 1)。系统提示词(人设 + 核心档案)和全部历史都留在可缓存的前缀里。这是借鉴 SillyTavern 1.17.0 的按深度注入,同时刻意偏离它的默认做法:它的总结扩展(`1_memory`)和向量记忆(`3_vectors`)默认放在 IN_PROMPT,也就是系统提示词里,每轮都会让缓存失效。

## Consequences

- 召回块只作用于当前这一轮,不写进历史;没有召回结果时也保留一个固定占位,保证后面的消息位置不变。
- 召回块内部顺序固定(核心档案摘要 → 事实库 → 情感库,每类再按记忆 ID 排序),不带时间戳,不放随机内容。
- 历史永不删改。超出上下文时一次截掉一大段,而且很少触发;截掉的部分先写入两个记忆库。不学 SillyTavern 向量扩展那样把召回到的旧消息从历史里移除。
- 关键词触发的条目由网关世界书负责,不用 Kelivo 世界书,这样电脑和手机只维护一份,注入内容也能进审计日志。
