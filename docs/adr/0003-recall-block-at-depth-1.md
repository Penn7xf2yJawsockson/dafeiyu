# 召回块固定插在深度 1,历史只追加

DeepSeek 的上下文缓存只看请求开头是否完全一致(前缀匹配),第一个不同的字之后全部按原价计费。召回内容每轮都会变,所以不放进系统提示词,而是作为一条 system 消息固定插在最新一条用户消息之前(深度 1)。系统提示词(人设 + 核心档案)和全部历史都留在可缓存的前缀里。这是借鉴 SillyTavern 1.17.0 的按深度注入,同时刻意偏离它的默认做法:它的总结扩展(`1_memory`)和向量记忆(`3_vectors`)默认放在 IN_PROMPT,也就是系统提示词里,每轮都会让缓存失效。

## Consequences

- 召回块第一行写当前本地时间(Asia/Shanghai),让模型知道今天几号;召回块每轮本来就会变,所以不影响缓存。带工具的一轮,召回块只在第一次请求时生成,后续工具回合原样复用。
- 召回块只作用于当前这一轮,不写进历史;没有召回结果时也保留一个固定占位,保证后面的消息位置不变。
- 召回块内部顺序固定(跨设备衔接 → 网关世界书 → 事实库 → 情感库;跨设备衔接保持时间顺序,其余每类按记忆 ID 排序),不带时间戳,不放随机内容。核心档案不在召回块里,而在系统提示词末尾。
- 历史永不删改。超出上下文时一次截掉一大段,而且很少触发;截掉的部分先写入两个记忆库。不学 SillyTavern 向量扩展那样把召回到的旧消息从历史里移除。
- 关键词触发的条目由网关世界书负责,不用 Kelivo 世界书,这样电脑和手机只维护一份,注入内容也能进审计日志。
- 实现(2026-10-29,工单 09):网关世界书采用 SillyTavern 世界书 JSON 格式、匹配规则与插入位置(按其行为重新实现,未拷贝其 AGPL 代码)。↑↓角色定义进第一条 system(人设之后、核心档案前后);@D 按条目的深度与角色插进历史,深度从本轮用户这句话往前数,召回块固定贴着用户这句话(深度 1 的条目在召回块之前);作者注释位置按 @D4 系统,示例位置并入 ↓角色定义,outlet 只替换 {{outlet::名字}}。概率与互斥组以本轮 ID 为随机种子,同一轮的工具回合结果相同。世界书匹配不经过召回超时,降级轮也注入。人设与核心档案始终在第一条 system,不按深度计。
