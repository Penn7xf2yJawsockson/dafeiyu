# 策划数据面板:人设、核心档案、网关世界书

打开 **http://127.0.0.1:18080/panel**(手机开着 Tailscale 时是 `http://dafeiyu:8080/panel`),用 `.env` 里的 `GATEWAY_PANEL_PASSWORD` 登录。这个密码只管面板,和设备 Token 无关。改动下一轮就生效,不用重启。

查看密码:`grep '^GATEWAY_PANEL_PASSWORD=' ~/dafeiyu/.env`

## 人设 / 核心档案

- **人设**:大肥鱼是谁、怎么说话,放在系统提示最前面。
- **核心档案**:关于你的关键事实,每一轮都带上,不靠检索;召回块里写着「事实冲突时以核心档案为准」。

两者的位置见下面「发给上游的消息排布」。

也可以直接用编辑器改 `data/gateway/persona.md`、`data/gateway/core_profile.md`。

## 发给上游的消息排布(注入深度)

从上到下(深度从本轮你说的那句话往前数,和酒馆一样只数真实的对话消息):

| # | 角色 | 深度 | 内容 |
|---|---|---|---|
| 1 | system | 最前 | **人设** → 世界书 ↑角色定义 → **核心档案** → 世界书 ↓角色定义,空一行拼成一条 |
| 2 | system | 最前 | 客户端自己的系统消息(Kelivo 助手设定、DSH 系统提示) |
| … | … | N…2 | 历史对话;世界书 @D 条目按深度插在其中 |
| | system | 1 | **召回块** `<memory>`:当前时间、跨设备衔接、相关事实、心里还挂着的事、相关经历与感受 |
| | user | 0 | 本轮你说的话 |
| | | 0 | 世界书 @D0 条目;之后是 DSH 注入的上下文、工具回合 |

所以**人设和核心档案不按深度算**:它们永远在第 1 条,在全部历史之前,不随对话变长而移动。这一段每轮不变,上游的缓存一直能命中。面板「注入预览」能看到某段对话实际的排布。

## 网关世界书

和酒馆(SillyTavern)的世界书是同一种格式:

- 酒馆导出的世界书 JSON,在面板「世界书 → 导入酒馆 JSON」导进来就能用;面板「导出」的文件也能导回酒馆,字段一个不丢。
- **设置分两层,和酒馆一样**:「世界书设置」= 酒馆世界书面板顶部的激活设置(扫描深度、预算、递归、大小写、整词),对所有书生效;每个条目可以单独设扫描深度、大小写、整词,留空用全局。酒馆没有「按整本书」的设置,网关也没有。
- 匹配规则和酒馆一样:主关键词(`/正则/` 也行)、次关键词 + 逻辑、常驻、停用、概率、互斥组、递归、顺序、预算。
- **插入位置也和酒馆一样**,每个条目单独设:

| 插入位置 | 网关里放在哪 |
|---|---|
| ↑角色定义 / ↓角色定义 | 第 1 条 system 里,人设之后、核心档案之前 / 核心档案之后 |
| @D(深度 + 角色) | 插进历史,深度 0 = 紧跟你这句话之后,1 = 紧挨在它之前(召回块前面),以此类推;角色可选 系统 / 用户 / AI;同深度同角色的条目合成一条 |
| ↑/↓作者注释 | 网关没有作者注释,按酒馆作者注释的默认位置放到 @D4 系统 |
| ↑/↓示例 | 网关没有示例对话,并入 ↓角色定义 |
| outlet | 不自动注入;在人设或核心档案里写 `{{outlet::名字}}`,就替换成这个 outlet 的条目 |

- 缓存提示:↑↓角色定义在第 1 条里,关键词条目时有时无,会让整段缓存失效;关键词触发的条目放 @D 更省,常驻条目放 ↑↓角色定义没问题。
- 记忆库出故障的降级轮,世界书照样注入。粘性、冷却、延迟、角色过滤网关不用,原样保留。

世界书文件在 `data/gateway/worlds/<名字>.json`,全局设置在 `data/gateway/lore_settings.json`。

## 版本与回滚

每次保存都会留一个版本;直接改文件也会在下一次读取时自动补记一版(来源显示「直接改文件」)。每一页都有「历史版本」,可以查看任何一版并回滚。删掉的世界书也能从历史里找回来。版本存在 `data/gateway/curated.sqlite3`。
