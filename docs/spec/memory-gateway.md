# 规格:记忆网关

> 状态:ready-for-agent。术语以 [CONTEXT.md](../../CONTEXT.md) 为准,决策理由见 [docs/adr/](../adr/)。

## Problem Statement

我想要一个能长期陪伴我的 AI「大肥鱼」,在 Windows 电脑和 Android 手机上的 Kelivo 里聊天。它要记得我说过的事,而且不能记错。可是:

- Kelivo 没有请求前后的 hook,也不能强制模型调用工具。把 Hindsight 和 Ombre-Brain 作为 MCP 工具挂上去,记不记、查不查都要看模型自己愿不愿意调,经常漏记、漏查。
- Hindsight 不保存原文,抽取漏掉的细节就永久丢了。Ombre-Brain 会把相似的记忆合并,还会按遗忘曲线自动归档。两个库单独拿出来,哪个都不能当作可靠的长期记录。
- 两台设备上的 Kelivo 各存一份聊天记录。在电脑上刚聊完,换到手机上,它就接不上话了。
- 每轮把召回的记忆塞进系统提示词,会让 DeepSeek 的前缀缓存全部失效,token 费用很高。
- 生日、重要的人这类关键事实,一旦说错,对陪伴体验的伤害很大。可检索本身是概率性的,做不到每次都对。

## Solution

在 Kelivo 和上游模型之间加一层**记忆网关**。对 Kelivo 来说,它就是一个普通的模型供应商。每一轮对话,网关都会确定性地做这些事:

1. 先把这一轮写进**原文日志**。原文日志是所有记忆的唯一真源。
2. 从事实库(Hindsight)和情感库(Ombre-Brain)召回记忆,组装成**召回块**,插在最新一条用户消息前面。
3. 用网关保存的**人设**和**核心档案**替换系统提示词,再转发给**上游**(DeepSeek 官方或中转,同时只用一个),把回复流式返回给 Kelivo。
4. 每一轮**确定**之后写入事实库;每一**段**对话结束后,整段写入情感库。

网关保证每一轮都一定执行召回和写入(**执行保证**),保证原文一定落盘、写入失败可以重放(**持久保证**)。召回内容是否恰好相关,不承诺 100%,但每轮用了哪些记忆都能查到(**可审计**)。**关键事实**不经过检索,每轮都确定性注入,而且必须先经过你本人确认。

网关只能从 Tailscale 私有网络访问。它和两个记忆库放在同一个 Docker Compose 里,运行在 Windows 的 WSL 中。

## User Stories

### 日常对话

1. 作为用户,我想在 Kelivo 里像连普通模型供应商一样连上大肥鱼,这样我不用学新的客户端。
2. 作为用户,我想在电脑和手机上用同一套配置连上网关,这样两端的大肥鱼是同一个"人"。
3. 作为用户,我想让 Kelivo 用 OpenAI 兼容格式连接网关,这样大多数供应商类型都能直接用。
4. 作为用户,我想让 Kelivo 也能用 Anthropic 格式连接网关,这样选 Claude 类供应商时也能用。
5. 作为用户,我想让回复像平时一样逐字流式显示,这样等待的感觉和直连模型一样。
6. 作为用户,我想在 Kelivo 里不写任何系统提示词,这样人设只需要在一个地方维护。
7. 作为用户,我想让大肥鱼每轮都知道我的核心档案,这样它永远不会叫错我、记错我的生日。
8. 作为用户,我想在提到以前的事时它能想起来,这样我不用一遍遍重复。
9. 作为用户,我想在新开一段对话时,它能主动提起还没解决、对我情绪影响大的事,这样它像真的在关心我。
10. 作为用户,我想让它只在相关时自然地提起过去,不要每句话都翻旧账,这样聊天自然。
11. 作为用户,我想在提到某个关键词(比如某个人名)时,网关世界书里对应的条目一定被带上,这样涉及这个人的事不会说错。
12. 作为用户,我想在一段对话里,开场的主动浮现只出现一次,这样它不会每轮重复同一件事。

### 跨设备

13. 作为用户,我想在电脑上聊完后,马上在手机上接着聊,它能接上刚才的话题,这样换设备不打断陪伴。
14. 作为用户,我想让跨设备衔接只带上另一台设备最近一段、而且是不久前结束的对话,这样不会把很久以前的内容硬塞进来。
15. 作为用户,我想让 Kelivo 屏幕上显示的历史,和模型实际看到的历史一致,这样编辑、重新生成、分支这些功能照常好用。
16. 作为用户,我想让网关通过各自的 Token 区分电脑和手机,这样衔接和审计都知道每一轮来自哪台设备。

### 记得准、不漏记

17. 作为用户,我想让每一轮无论模型愿不愿意,都一定被记录,这样不会因为模型偷懒而漏记。
18. 作为用户,我想让每一轮的原文先保存到网关自己的日志,这样即使某个记忆库坏了,内容也能找回。
19. 作为用户,我想让我在 Kelivo 里重新生成或编辑过的旧版本不进入记忆,这样被我放弃的回复和改掉的话不会被当成事实。
20. 作为用户,我想让被取代的旧版本仍然保留在原文日志里,这样以后能查清发生过什么。
21. 作为用户,我想让我说的新事实在下一轮就能被事实库查到,这样信息更新很及时。
22. 作为用户,我想让一段对话结束后,整段作为一件事写进情感库,这样情感记忆是完整的事件,而不是零碎的句子。
23. 作为用户,我想让一段对话在我空闲 30 分钟后,或者满 20 轮时自动结束,这样不需要我手动结束对话。
24. 作为用户,我想让电脑关机前还没写进记忆库的内容,下次启动时自动补写,这样关机不会丢记忆。
25. 作为用户,我想让记忆库写入失败时自动重试,直到成功,这样一次网络抖动不会丢记忆。
26. 作为用户,我想让任何一个记忆库都能从原文日志完整重建,这样换库、升级或者数据损坏都不怕。

### 关键事实与确认

27. 作为用户,我想让网关自动发现看起来像关键事实的内容,并提给我确认,这样我不用自己整理档案。
28. 作为用户,我想让还没确认的事实不会被每轮强制注入,这样抽取出错的内容不会被当成铁律。
29. 作为用户,我想在手机浏览器里打开确认面板,一键确认、修改或拒绝待确认事实,这样维护很轻松。
30. 作为用户,我想直接编辑核心档案、网关世界书和人设,这样我能完全掌控它"认识"的我和它自己。
31. 作为用户,我想让核心档案、网关世界书和人设的每次修改都有版本记录,并且能回滚,这样改错了能恢复。
32. 作为用户,我想让每条关键事实都能追溯到原文日志里的某一轮,这样我能核对它是从哪句话来的。

### 遗忘

33. 作为用户,我想把某一轮或某条记忆「隐藏」,让它不再被提起,这样不想再谈的事就不会被翻出来。
34. 作为用户,我想撤销隐藏,这样我改变主意后还能找回来。
35. 作为用户,我想让被隐藏的内容在重建记忆库时也不会回来,这样隐藏是长期有效的。
36. 作为用户,我想「抹除」某些内容,让它从原文日志、两个记忆库、原文证据和审计记录里全部物理删除,这样误发的隐私能彻底消失。
37. 作为用户,我想让抹除前必须二次确认,这样不会误删。
38. 作为用户,我想在抹除完成后收到提醒,告诉我还有哪些地方可能留有副本(比如 Ombre 的 GitHub 同步历史),这样我知道还要处理什么。

### 出错与降级

39. 作为用户,我想在某个记忆库挂了或召回太慢(约 3 秒)时,仍然收到回复,这样陪伴不会被打断。
40. 作为用户,我想让降级的回复带一个可见标记,这样我知道这一轮它的记忆可能不完整。
41. 作为用户,我想让降级轮中核心档案和网关世界书照常注入,这样最关键的事实在降级时也不会说错。
42. 作为用户,我想在上游出错时看到明确的错误,而不是一个没有记忆的回复,这样我知道该点重新生成。
43. 作为用户,我想在网关配置里切换官方 API 和中转,这样换上游不用改 Kelivo。

### 省 token

44. 作为用户,我想让人设、核心档案和全部历史在连续几轮之间保持完全一样,这样 DeepSeek 的前缀缓存能一直命中。
45. 作为用户,我想让召回块只作用于当前这一轮,不写进历史,这样历史前缀不会每轮变化。
46. 作为用户,我想让没有召回结果时也保留固定的占位,这样后面消息的位置不会跳动。
47. 作为用户,我想让召回块里的内容顺序固定,不带时间戳和随机内容,这样同样的召回结果每次渲染都一样。
48. 作为用户,我想让历史超出上下文时一次截掉一大段、很少触发,并且截之前先确保这段已经写进记忆库,这样截断既少影响缓存,也不丢信息。

### 审计与运维

49. 作为用户,我想查看每一轮注入了哪些记忆(按记忆 ID)、是否降级、用了哪个上游,这样它说错话时我能查到原因。
50. 作为用户,我想让 Windows 开机后网关和两个记忆库自动启动,并且 WSL 空闲时不会自动关闭,这样手机随时能用。
51. 作为用户,我想让手机只通过 Tailscale 私有网络访问网关,这样记忆服务不暴露在公网上。
52. 作为用户,我想让两个记忆库只有网关能访问,这样不会有别的程序绕过网关直接读写记忆。
53. 作为用户,我想让原文日志、核心档案、网关世界书和人设每天自动备份到 E 盘,这样系统盘坏了也不会丢失全部记忆。
54. 作为用户,我想定期验证备份能正常恢复,这样真出事时备份是可用的。
55. 作为开发者,我想让每一轮都标注所属的陪伴角色,这样以后增加角色时不用推翻现有结构。
56. 作为开发者,我想让公开仓库里永远没有密钥和记忆数据,这样仓库可以公开。

## Implementation Decisions

### 模块

记忆网关是一个 Python + FastAPI 服务(ADR-0008),内部按职责分成以下模块,对外只暴露 HTTP 接口:

- **入口适配(Ingress)**:提供 OpenAI 兼容的 `/v1/chat/completions` 和 Anthropic 兼容的 `/v1/messages`,把两种格式统一转换成内部的"一轮请求",回复时再转回原格式(包括流式)。按 Bearer Token 识别设备,未知 Token 返回 401。
- **原文日志(Transcript Log)**:只追加的逐轮记录,是唯一真源(ADR-0001)。每一轮都记录这些字段:设备、陪伴角色、段、内容哈希、状态(待定 / 确定 / 已取代 / 已隐藏)、时间。被抹除的轮会被物理删除。
- **轮状态机(Turn Lifecycle)**:收到新请求时,把 Kelivo 发来的历史和原文日志对比,判断上一轮是确定了还是已被取代,并识别段的开始和结束。
- **召回编排(Recall Orchestrator)**:并发调用事实库、情感库、网关世界书和跨设备衔接,总超时约 3 秒;超时或出错的来源跳过,这一轮标为降级轮。
- **提示词组装(Prompt Composer)**:负责人设替换、核心档案位置和召回块注入(ADR-0003)。
- **上游客户端(Upstream Client)**:同时只配置一个上游,流式转发;出错时把错误原样返回,不重试,也不切换到别的上游。
- **写入队列(Write Outbox)**:持久化的待写入任务,失败按指数退避重试,网关启动时从原文日志对账、补写。
- **记忆库适配(Store Adapters)**:事实库适配走 Hindsight REST,情感库适配走 Ombre MCP 或 REST。适配层把两个库的细节挡在内部,向上只提供"召回"和"写入"两类操作。
- **策划数据(Curated Data)**:人设、核心档案、网关世界书、待确认事实,全部带版本,可以回滚。
- **面板与管理接口(Panel)**:提供确认、编辑、隐藏、抹除、审计查询的网页和 API,由面板单独的密码保护。
- **审计(Audit)**:每一轮记录注入了哪些记忆 ID、来源、是否降级、是否失败、上游和用时。

### 每一轮的处理顺序

1. 用 Token 识别设备,再按模型名(预留)识别陪伴角色。
2. 轮状态机处理上一轮:如果本轮之前的历史和上一轮之前的历史相同(也就是用户重新生成,或编辑了上一句),把上一轮的旧版本标为已取代,新版本当作新的一轮记录;重新生成失败时撤销取代。其他情况,包括接着聊下去和在 Kelivo 里新开一个对话,上一轮都标为确定轮,把写入事实库的任务放进写入队列。新开对话不等于否定上一轮(用户 2026-10-29 确认)。在对话开头,编辑第一句和新开一个对话的历史长得一样,这时按文字相似度区分:几乎相同算编辑或重新生成,完全不同算新开对话。
3. 把当前这一轮作为待定轮写进原文日志。
4. 收到 Kelivo 的「压缩上下文」请求时(按默认提示词识别,不论走哪个模型):立刻结束这台设备当前的段,待定轮全部确定,写入两个记忆库;压缩请求本身照常转发,不记成一轮。
5. 判断是不是段的第一轮:距离上一轮超过 30 分钟就开始新的一段,同一段满 20 轮也开始新的一段。旧的一段结束时,最后一轮标为确定,再把整段写入情感库的任务放进写入队列。
6. 召回:
   - 每一轮:事实库 recall;情感库 `breath_search(mode="automatic", with_ids=True)`;网关世界书按关键词匹配。
   - 只在段的第一轮:情感库 `breath`;跨设备衔接,也就是另一台设备最近一段结束不到 6 小时时,带上那一段最后 6 轮原文。
7. 组装请求,转发给上游,把回复流式返回给 Kelivo,同时把回复完整写进原文日志里的这一轮。
8. 写审计记录。

### 提示词结构(ADR-0003)

```
system:    [人设][核心档案]                       ← 很少变化,可以缓存
history:   [Kelivo 发来的历史,原样保留,只追加]      ← 可以缓存
system:    <memory>[召回块]</memory>              ← 深度 1,每轮都会变
user:      [最新一条消息]
(assistant 预填,可选,放在最后)
```

- 网关保存的人设和核心档案放在最前面;Kelivo 发来的 system 消息(技能列表、搜索引用规则等)保留,放在它们之后(实测抓包后修改)。人设为空时不发空的 system 消息。
- 召回块的内部顺序固定:跨设备衔接 → 网关世界书命中 → 事实库结果 → 情感浮现 → 情感库检索结果。跨设备衔接保持对话的时间顺序,其余同一类内部按记忆 ID 排序。不加时间戳,不放随机内容。
- 没有召回结果时,召回块写成固定的占位文本,不省略这条消息。
- 召回块里写明使用规则:只在相关时自然提及;事实冲突时以核心档案为准。
- 召回块**不写进原文日志里的历史**。原文日志只保存 Kelivo 发来的消息和上游返回的回复;召回块的内容通过审计里的记忆 ID 来追溯。

### 记忆库映射

- **事实库(Hindsight)**:单 bank。每一段用一个 `document_id`,每次都 retain 这一段全部已确定的原文。同一 `document_id` 再次 retain 会整体替换,所以写入天然幂等,隐藏和抹除也只是"不带那一轮重新 retain"。没有用 `update_mode="append"`:append 在重试时会重复追加。Hindsight 文档说没变的块会跳过,但整段替换的抽取成本要用契约测试确认,成本过高时再改成按轮 append 加幂等的 `operation_id`。recall 设置 `max_tokens` 上限;`query_timestamp` 还没接入,默认用服务器时间。
- **情感库(Ombre-Brain)**:单实例。段结束时把整段原文交给 `grow`。召回解析 `ombre:result-ids` 块拿到 ID,作为审计依据。隐藏时调用归档,并设为 `dont_surface`。抹除时绕过 Ombre,直接删除它的 Markdown 文件和 `_sources/` 原文证据,然后重建索引(ADR-0005)。
- 两个库的 MCP 都不挂在 Kelivo 上,只有网关能访问它们(ADR-0002、ADR-0006)。

### 模型配置(ADR-0007)

- 事实抽取、情感打标:`deepseek-flash`。打标时关闭 thinking,`max_tokens` 设为 4096。
- 向量化:硅基流动的 `BAAI/bge-m3`,两个库共用。
- 重排序:硅基流动的 `BAAI/bge-reranker-v2-m3`,使用 Hindsight 原生的 `siliconflow` provider。

### 待确认事实

- 网关在每轮确定后,从 Hindsight 新抽取出的事实里,按规则(人名、关系、日期、身份、重大事件)挑出候选,放进待确认列表,并记下它来自原文日志的哪一轮。
- 待确认事实不进入核心档案和网关世界书,但仍然可以通过事实库被检索到。
- 在面板上确认后,它成为关键事实,归入核心档案(每轮都注入)或网关世界书(按关键词触发),由你选择。

### 遗忘

- **隐藏**:原文日志里把这一轮标为已隐藏;事实库重新 retain 这一段,跳过这一轮;情感库归档对应的记忆,并设为 `dont_surface`。可以撤销,撤销时反向执行。
- **抹除**:先执行隐藏,再物理删除这五处:原文日志里这一轮的原文、Ombre 的 Markdown 文件、Ombre 的原文证据、审计记录里的相关内容、Hindsight 里的旧文档(先删除,再重新 retain)。抹除需要二次确认,完成后列出可能还有副本的地方。

### 部署

- 一个 Docker Compose 文件,包含网关、Hindsight(含 PostgreSQL)、Ombre 三个服务,运行在 WSL 里。两个记忆库只在 Compose 内网可以访问。
- 网关端口通过 Windows 端口转发提供给 Tailscale。Win10 22H2 不支持 WSL 的 mirrored 网络模式。
- Windows 开机后自动启动 WSL 和这个 Compose 项目,并且防止 WSL 空闲时自动关闭。
- 数据都放在 `data/` 目录,已被 `.gitignore` 排除。每天把原文日志、人设、核心档案、网关世界书备份到 E 盘。

## Testing Decisions

### 什么是好测试

- 只测外部行为:从 HTTP 接口输入,观察上游收到了什么、记忆库收到了什么、Kelivo 收到了什么、原文日志和审计里有什么。不断言内部函数怎么调用、模块怎么拆分。
- 每条测试对应一条用户故事或一条 ADR 约束,测试名直接写成那条行为,例如「编辑过的上一轮不写入事实库」。
- 时间相关的行为(空闲 30 分钟、6 小时内的跨设备衔接)用可控时钟推进,不靠真实等待。

### 主要切入点:网关 HTTP 接口

测试只从入口调用网关:两个对话接口,加上面板和管理接口。外部依赖全部换成测试用的假服务:

- **假上游**:记录收到的完整请求;按脚本返回流式或非流式回复;能模拟开始输出前报错,以及输出到一半断开。
- **假事实库、假情感库**:记录全部写入;按脚本返回召回结果和记忆 ID;能模拟超时和宕机。
- **可控时钟**。

要覆盖的行为(不完全列表):

- 人设替换:Kelivo 发来的系统提示词被丢弃;上游收到的系统提示词以人设开头,后面是核心档案。
- 缓存前缀稳定:连续多轮中,上游收到的请求从开头到召回块之前完全一致,包括召回结果为空、降级轮这两种情况。
- 召回块固定在深度 1;内容顺序固定;没有召回结果时有占位;召回块不出现在后续轮的历史里。
- 确定轮与已取代:上一轮没被改动,才写入事实库;编辑或重新生成后,旧版本不写入任何记忆库,但原文日志里保留,并标为已取代。
- 段:空闲超过 30 分钟或满 20 轮开启新的一段;段结束时情感库只收到一次整段写入;情感浮现只在段的第一轮出现。
- 跨设备衔接:另一台设备的上一段结束不到 6 小时,召回块里带上它最后 6 轮;超过 6 小时,或者是同一台设备,就不带。
- 降级:任意一个记忆库超时或报错时,回复照常返回并带可见标记,审计记为降级,核心档案和网关世界书仍然注入。
- 上游失败:错误返回给 Kelivo,审计记为失败,不重试,也不切换上游。
- 持久:记忆库写入失败后自动重试;网关重启后,能从原文日志补写未完成的任务。
- 网关世界书:命中关键词时条目一定注入;没命中时不注入。
- 待确认事实:候选不进入确定性注入;在面板确认后,下一轮出现在核心档案或网关世界书里。
- 隐藏 / 抹除:隐藏后重建事实库,不包含那一轮;撤销后恢复;抹除后原文日志和审计里查不到原文。
- 两种入口格式:OpenAI 和 Anthropic 的请求进入网关后,上游收到的内容等价,流式回复都能正确转回原格式。
- 鉴权:未知 Token 返回 401;不同设备的 Token 在审计里能区分开。

### 补充切入点:真实服务契约测试

在 Docker 里起真实的 Hindsight 和 Ombre,只验证假服务模拟不了的几件事。这类测试不放进日常测试,单独运行:

- Ombre 打标配置 `thinking: disabled` 真的生效,长内容 `grow` 不会因为推理把预算用完而失败。
- 同一段文本分别请求免费版和 Pro 版 bge-m3,得到的向量一致(在决定是否允许混用之前先确认这一点)。
- `breath_search(mode="automatic", with_ids=True)` 返回的 ID 块能被正确解析。
- Hindsight 用同一个 `document_id` 重新 retain 后,旧的事实被替换,不会产生重复。
- 抹除后,Ombre 的 Markdown 文件和 `_sources/` 原文证据确实被删除,`breath_search` 搜不到。
- 硅基流动重排序在中文查询下能正常返回结果。

### 已有可参考的测试

这个仓库还没有代码,也没有测试。可以参考上游项目的做法:Ombre-Brain 用回归测试钉住了 `with_ids` 契约(`tests/test_breath_call_mode.py`),也有检索质量自测脚本(Hit@K、MRR)。网关的检索质量可以借用同样的指标,但不放进日常测试。

备份与恢复演练是脚本,单独验收,不放在上面两类测试里。

## Out of Scope

- 多个陪伴角色(只预留标注,不实现第二个角色)。
- 不记录的临时对话通道(Q11 决定不做)。
- 主备上游、自动切换上游。
- 异地备份(只备份到本机 E 盘)。
- 公网访问(Cloudflare Tunnel 等)。
- Kelivo 自带的记忆、`chat_search` 和世界书(都关闭不用)。
- 把两个记忆库的 MCP 直接挂给模型。
- Ombre 的 `dream`、`letter`、`I`、`You`、`them` 这些需要模型主动调用的能力。
- 修改 Kelivo、Hindsight 或 Ombre-Brain 的源码。抹除时直接删 Ombre 文件,是唯一一处绕开上游设计的地方。
- 召回相关性做到 100%。
